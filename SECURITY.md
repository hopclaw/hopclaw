# Security Policy

## Supported Releases

Security fixes are prioritized for:

- the latest tagged public release
- the current pre-release channel when a beta or nightly build is explicitly
  announced

Older releases may not receive fixes.

## Reporting A Vulnerability

Do not open a public GitHub issue for a security-sensitive report.

Preferred reporting path:

1. Use GitHub private vulnerability reporting for this repository if it is
   enabled.
2. If private reporting is not enabled yet, use the official contact path on
   https://hopclaw.com and clearly mark the report as security-sensitive.

Please include:

- affected version and platform
- the surface involved, such as runtime, gateway, channel, browser helper,
  desktop helper, install flow, or release artifacts
- reproduction steps or a minimal proof of concept
- expected impact
- whether secrets, approvals, artifacts, or persistence boundaries are involved

If useful, attach a redacted bundle generated by `hopclaw bug-report`.

## Response Targets

- initial acknowledgment within 5 business days
- triage when the issue is reproducible
- fix timing based on severity, exploitability, and release risk

## Scope

Security reports are especially helpful for issues involving:

- authentication, authorization, or approval bypass
- unsafe tool execution, command filtering bypass, or sandbox escape
- secret exposure in logs, config, artifacts, or update flows
- release artifact tampering, checksum verification, or install trust
- cross-session, cross-workspace, or cross-tenant data exposure

## 简体中文

## 支持范围

安全修复会优先覆盖：

- 最新公开 tag 版本
- 已明确公告的 beta 或 nightly 预发布通道

较老版本不保证继续提供安全修复。

## 漏洞报告方式

请不要通过公开 GitHub issue 提交安全问题。

推荐路径：

1. 如果这个仓库启用了 GitHub 私密漏洞报告，优先使用该入口。
2. 如果暂时还没启用，请通过 https://hopclaw.com 的官方联系路径提交，
   并明确标注为安全问题。

请尽量提供：

- 受影响的版本和平台
- 相关能力面，例如 runtime、gateway、channel、browser helper、
  desktop helper、安装流程或 release 产物
- 复现步骤或最小 PoC
- 预期影响
- 是否涉及 secrets、approvals、artifacts 或持久化边界

如果有帮助，可以附上由 `hopclaw bug-report` 生成并已脱敏的问题包。

## 响应目标

- 5 个工作日内给出初次确认
- 可以复现时进入分级和 triage
- 修复节奏按严重性、可利用性和发布风险决定

## 重点范围

以下方向的安全报告尤其有价值：

- 认证、授权或审批绕过
- 不安全的工具执行、命令过滤绕过或沙箱逃逸
- secrets 在日志、配置、artifacts 或更新流程中的暴露
- release 产物篡改、校验和校验或安装信任链问题
- 跨 session、跨 workspace 或跨租户的数据暴露
